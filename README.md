# RelocateSpend

Учёт расходов после переезда: ручной ввод и QR-чеки Сербии, категории, графики, три языка (ru / en / sr), светлая и тёмная тема по макету.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # проверка типов + production-сборка
npm run typecheck
npm run lint
```

## Что было не так в прошлой версии

| Проблема | Причина | Как сейчас |
|---|---|---|
| **Белый экран при запуске** | `import { useApp, Currency } from '../store'` и `import { ReactNode } from 'react'` — типы импортировались как значения. При `verbatimModuleSyntax` такие импорты не вырезаются, браузер падал с `SyntaxError: does not provide an export named 'Currency'` ещё до рендера | Все типы импортируются через `import type` / `type X` |
| Белый экран при битых данных | `JSON.parse(localStorage…)` без защиты | Данные проходят валидацию (`store/storage.ts`), битый JSON откладывается в резервный ключ |
| Падение при добавлении траты с телефона по `http://192.168…` | `crypto.randomUUID` есть только в secure context | `shared/lib/id.ts` с запасным генератором |
| Даты «съезжали» на день | `new Date('2026-11-09')` парсится как UTC | Даты хранятся как `YYYY-MM-DD`, всё считается в `shared/lib/date.ts` |
| «Расходы за месяц» считали всё время | Не было фильтра по периоду | Периоды неделя / месяц / год / свой, сравнение с прошлым |
| Курс всегда 1, смена базовой валюты ломала суммы | `amountInBase` с заглушкой | У расхода хранится курс на дату покупки (`eurRate`), пересчёт в любую валюту |
| Мутация состояния в форме позиций | `n[idx].name = …` | Иммутабельные операции в `useExpenseDraft` |
| Системная тема не реагировала на переключение ОС | Проверка один раз | `useSyncExternalStore` + `matchMedia` |
| Язык в настройках ничего не менял | Не было i18n | Типизированные словари ru / en / sr |
| `confirm()` для удаления, `as any` | — | Свои диалоги в стиле iOS, строгая типизация |

Старые данные (ключ `relocate-spend-data`) автоматически переносятся в новый формат при первом запуске.

## Как пользоваться

- **Расход в списке:** нажатие открывает страницу чека, свайп влево показывает «Изменить» и «Открыть». Удаление — внутри чека.
- **Позиции** вводятся таблицей: Enter переходит к цене и к следующей строке, пустая строка добавляется сама. Можно вставить сразу список строк вида «Молоко 590» (из заметок или чека) — он разберётся на позиции. Если позиции есть, сумма расхода по умолчанию равна их сумме (тумблер «Сумма расхода = сумма позиций», одинаковый в форме и в шторке позиций, запоминается для каждого чека — поле `amountFromItems`).
- **Валюта, категория, язык и тема** применяются сразу по нажатию, без кнопки «Готово».
- **Под суммой** показываются примерные суммы во всех остальных валютах.
- **Кольцо трат** — сегменты с зазорами, проценты снаружи, категории и суммы плашками ниже. **Карусель:** по бокам выглядывают кольца соседних периодов, свайп вправо — прошлый, влево — следующий (в будущее нельзя). Столбцы листаются так же. В календаре месяцы тоже листаются свайпом.
- **Шторки** закрываются смахиванием вниз за шапку.
- **Лимит QR-чеков** (15 в месяц на Free) считается по журналу сканов (`state.scans`), а не по расходам: удаление расхода не возвращает скан, повторный скан того же чека не тратит лимит.

## Публикация, база и аналитика

Пошаговая инструкция — **[docs/DEPLOY.md](docs/DEPLOY.md)**: Supabase (вход и синхронизация), PostHog (статистика), Cloudflare Pages (хостинг), Telegram-уведомления об отзывах.

Коротко:
- **Одна кодовая база — две копии:** ветка `main` → production для людей, ветка `dev` → тестовая копия со своей базой. Чем копии различаются, задают переменные `VITE_*` (см. `.env.example`).
- **Без переменных** (локально, без `.env.local`) приложение работает как раньше: данные только на устройстве, без входа и отзывов.
- **Аккаунт необязательный.** Без него данные в `localStorage`. После входа `store/sync` в фоне синхронизирует их с таблицей `records`: забирает изменения из облака → отправляет локальные. При первом входе траты с телефона переносятся в аккаунт.
- **Вход по почте и паролю** — Supabase Auth через REST (`shared/api/supabase`), без SDK. Подтверждение почты и сброс пароля — по **коду** из письма, а не по ссылке: на iPhone ссылка открылась бы в Safari, а не в установленном приложении.
- **Аналитика** — PostHog через HTTP API (`shared/analytics`). Отправляются только события, без сумм, названий и почты. Её можно выключить в профиле.
- **Обновления:** при сборке создаётся `version.json`. Открытое приложение сверяет его со своей версией и показывает плашку «Доступна новая версия». Новинки показываются в окне «Что нового» (`features/app-update/releases.ts`).
- После первого открытия приложение работает **без интернета** (service worker `public/sw.js`, список файлов вписывает `scripts/postbuild.mjs`).

## Иконка и установка на телефон

Логотип (кольцо трат со стрелкой на тёмном фоне) — `public/logo.svg`. Иконки: `apple-touch-icon.png` (iPhone, «На экран Домой»), `icon-192/512.png` и `icon-maskable-512.png` (Android), манифест — `public/manifest.webmanifest`. Приложение открывается с главного экрана без адресной строки.

## Архитектура

Слои (импорт разрешён только «вниз»):

```
app        → провайдеры, роутинг, таб-бар, глобальные стили, ErrorBoundary
pages      → экраны (home, add-expense, expense-details, scan, profile, …)
widgets    → крупные блоки экранов (spending-overview, expense-list)
features   → пользовательские сценарии (period, expense-form, category, expense-filters, receipt-scan, …)
store      → состояние приложения: reducer, actions, хранилище
entities   → модели и чистые функции (expense, category)
shared     → UI-кит, i18n, утилиты, конфиг — ничего не знает о предметной области
```

- **Состояние** — `useReducer` + контекст (`src/store`). Reducer чистый; id, время и курсы проставляются в `actions.ts`. Хранилище спрятано за интерфейсом `StateRepository`: чтобы перейти на сервер, достаточно написать новую реализацию `load` / `save`.
- **Стили** — CSS Modules + дизайн-токены в `app/styles/tokens.css`. Тема переключается атрибутом `data-theme` на `<html>`, компоненты используют только переменные. Цвета категорий — токены `c1…c8`, каждая тема рисует их по-своему (как в макете).
- **i18n** — `shared/i18n/locales/ru.ts` — эталон. `en` и `sr` типизированы по нему: пропущенный ключ — ошибка компиляции. Множественное число через `Intl.PluralRules`, даты и числа через `Intl`.
- **Экраны** грузятся лениво (`React.lazy`) — стартовый бандл не растёт с числом экранов.
- Алиас `@/` → `src/`.

### Как добавить…

- **валюту** — `shared/config/currency.ts` (код + курс) и `currency.<CODE>` в словари;
- **язык** — файл в `shared/i18n/locales`, запись в `LANGUAGES` / `LANGUAGE_META` (`shared/i18n/core.ts`);
- **значок категории** — иконку в `shared/ui/Icon/Icon.tsx` и id в `CATEGORY_ICONS`;
- **поле расхода** — тип в `entities/expense/model.ts`, валидацию в `store/storage.ts`, поле в `features/expense-form`. Если меняется формат хранения — поднять `SCHEMA_VERSION` и дописать миграцию;
- **экран** — папку в `pages/`, путь в `shared/config/routes.ts`, `Route` в `app/layout/AppLayout.tsx`.

## Бета-тест: что включено

Незаконченные функции выключены флагами в `src/shared/config/features.ts`. Флаг можно включить без пересборки — в таблице `app_config` в Supabase (у всех пользователей на следующем запуске) — или только для тестовой копии через `VITE_FEATURES`:

| Флаг | Сейчас | Что видит пользователь |
|---|---|---|
| `qrScan` | `false` | Плашка «Есть чек? Отсканируйте» с меткой «Скоро» → окно «тестовый период, скоро появится». Камера, демо-чек и `/scan` недоступны |
| `pro` | `false` | Тариф, лимит сканов и экран Pro скрыты, `/profile/pro` ведёт в профиль |

При первом запуске показывается обучение из 4 слайдов (`features/onboarding`), затем — подсказка «На главный экран». Повторить обучение: «Профиль → Как пользоваться приложением».

## Что пока работает как заглушка

- **Данные QR-чека.** Сайт `suf.purs.gov.rs` не отдаёт CORS-заголовки, поэтому прочитать чек прямо из браузера нельзя — нужен свой бэкенд-прокси. Укажите его в `.env` (`VITE_RECEIPT_API_URL`, см. `.env.example` и `features/receipt-scan/receiptService.ts`). Без него в dev-режиме есть кнопка «Демо-чек», а в production пользователь видит честное «распознавание пока недоступно».
- **Распознавание QR** — встроенный в браузер `BarcodeDetector` (Chrome/Edge на Android, Safari 17+). Где его нет, предлагается ручной ввод.
- **Курсы валют** — фиксированная таблица в `shared/config/currency.ts`; точка подключения реального API — `ratesService` в `shared/lib/money.ts`.
- **Pro и оплата** — тариф хранится в таблице `profiles` (`plan`), но оплата ещё не подключена: экран Pro скрыт флагом `pro`.
