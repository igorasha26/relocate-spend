### 1. Курсы валют — обязательно
**Проблема:** курсы, скорее всего, зашиты в код, и пересчёт RSD ↔ EUR ↔ RUB ↔ USD со временем расходится с реальным. *(Первым делом проверить, откуда сейчас берутся курсы.)*

**Что сделать:**
- Раз в сутки подтягивать свежие курсы из бесплатного источника без ключа, в котором есть **RSD и RUB**. У ЕЦБ рубля нет, поэтому кандидат — open.er-api.com. Источник выбрать и проверить завтра.
- Хранить последние курсы на телефоне, чтобы офлайн всё считалось.
- Новая трата запоминает курс на момент записи (как сейчас `eurRate`): старые траты не пересчитываются задним числом.
- Если источник недоступен — работать на последних сохранённых или встроенных курсах.
- Где-нибудь мелко показать дату курса: «Курс на 12.11».
- *Вариант надёжнее:* курсы раз в день забирает сама база (Supabase, задача по расписанию), а приложение читает их из таблицы. Тогда не зависим от лимитов внешнего сервиса на каждом телефоне. Решить завтра.

### 2. Капча на регистрацию и отзывы
**Зачем:** боты могут засыпать регистрацию и форму отзывов. Каждая фейковая регистрация — письмо, а бесплатный Resend отправляет только 100 писем в день.

**Что сделать:**
- **Cloudflare Turnstile** — бесплатная и почти незаметная для человека капча. Supabase поддерживает её «из коробки».
- Шаги Игоря: Cloudflare → Turnstile → добавить сайт (`app.relocatespend.app`, `dev.relocate-spend.pages.dev`, `localhost`) → получить Site key и Secret key → Secret вставить в Supabase (Authentication → Bot and Abuse Protection) в обоих проектах.
- Шаги в коде: виджет Turnstile на экранах «Регистрация», «Вход», «Забыли пароль?»; токен уходит вместе с запросом в Supabase.
- Отзывы: та же капча или ограничение частоты отправки в базе (не больше N отзывов в час с одного устройства).

### 3. Сбор ошибок — бесплатно
- В PostHog есть бесплатный сбор ошибок (Error tracking, до 100 тысяч ошибок в месяц). Отдельный сервис не нужен.
- В коде: отправлять в PostHog необработанные ошибки и падения экранов (ErrorBoundary), с версией приложения, экраном и типом устройства — без данных пользователя.
- Игорь смотрит ошибки в PostHog → Error tracking. По желанию — уведомление в Telegram о новых ошибках.

### 4. Почта — решить по деньгам
- **Сейчас (бесплатно):** Resend, 3000 писем в месяц, но **не больше 100 в день**. На паузе этого хватает.
- **Resend Pro — $20 в месяц:** 50 000 писем, без дневного лимита. Переходить, когда пойдёт реклама в группах.
- **Бесплатный выход на время рекламы:** выключить в Supabase *Confirm email*. Регистрация пройдёт без письма, но тогда письма понадобятся только для «Забыли пароль?».
- **Решение:** пока остаёмся на бесплатном. Перед первым крупным постом выбрать: $20 или выключить подтверждение.

### 5. Supabase Pro — пока не подключаем
- Бесплатного хватит примерно на 1–2 тысячи пользователей.
- Риск: на бесплатном плане нет резервных копий. Вернуться к вопросу, когда появятся десятки настоящих пользователей ($25 в месяц: бэкапы, 8 ГБ, без засыпания).
- Тестовая база засыпает после недели без входа: в Supabase нажать **Restore**.

## Совместный бюджет — решения от 13.11

**Решено Игорем:**
- Можно создать **группу трат** (например «Дом», «Поездка»). Приглашать в неё никого не обязательно: группа может быть просто отдельной копилкой трат.
- В группе **до 5 человек**, приглашение — по почте.
- Расчёт «кто кому должен» **пока не делаем**.
- **Автор траты** показывается в карточке траты: цветной овал с именем (у каждого участника свой цвет).
- **Своих категорий у группы нет**, у группы есть только название. Если трата в группе записана в чью-то личную категорию, она переносится вместе с названием, цветом и иконкой этой категории — остальные участники видят её правильно.
- **Личные траты можно перенести в группу.** Перенос, а не копия: иначе во вкладке «Все» трата посчитается дважды.

**Создание группы (решено 13.11):** название → шаг «Перенести уже записанные траты?»: список личных трат с галочками, кнопка **«Выбрать все»** и «Пропустить» → дальше по желанию пригласить людей по почте (тоже можно пропустить).

**Перенос личных трат в группу (предложение):**
1. **Одну трату:** в карточке траты кнопка «Перенести в группу…» и то же действие в свайпе.
2. **Сразу несколько:** в списке «Все расходы» кнопка «Выбрать» → отметить траты галочками → «Перенести в группу».
3. **Быстрый перенос по правилу:** «все траты категории Продукты с 1 ноября» (можно позже).
- Дата, сумма и курс перенесённой траты не меняются. Автор — тот, кто переносит.
- Вернуть трату в личные может только её автор.

**Правила группы (решено 13.11):**
- **Все участники равны.** Добавлять, менять и удалять любые траты группы может любой участник. Создатель ничем не отличается от остальных.
- **Удалить группу нельзя — можно только выйти.** Траты вышедшего остаются в группе с его именем.
- **Последний участник вышел → группа удаляется вместе с её тратами.** Последнему перед выходом показывается предупреждение и выбор: «Забрать траты группы в личные» или «Удалить вместе с группой» (решено: делаем).
- Можно состоять **в нескольких группах**, переключатель на главной: «Все · Личные · Дом · Поездка…» (принято по умолчанию).
- **Автор траты** — цветной овал с именем в карточке траты; цвет закреплён за участником в группе (принято по умолчанию).
- В карточке траты видно и **кто последним изменил** трату, если это не автор: «Добавил Игорь · изменила Аня».

**Как примерно устроено:**
- В базе появляются группы (`budgets`), участники (`budget_members`) и приглашения (`invites`: почта, срок действия 7 дней).
- Траты и категории принадлежат бюджету. Правило доступа: видят все участники.
- Новая трата появляется у второго человека почти сразу (обновление в реальном времени).
- Текущие траты автоматически переезжают в личный бюджет.
- Сначала только тестовая копия, проверка на двух телефонах, потом прод.
- Синхронизацию нужно доработать: двое могут менять одну трату одновременно.


**Оценка:** 3–4 дня работы плюс проверка.

**Этапы работы:**
1. ✅ (13.11) База: группы, участники, приглашения, права доступа (все участники равны), удаление группы без участников. Синхронизация по группам. Перенос трат в группу и обратно.
2. Экраны: создание группы с шагом переноса трат («Выбрать все»), список групп в профиле, участники, выход с предупреждением последнему.

5. Проверка на двух телефонах на тестовой копии → выпуск в основную.
